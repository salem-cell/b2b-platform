# منصة B2B — الطلب والتوريد للمطاعم (نسخة الويب)

تطبيق ويب كامل مبني من تصميم Claude Design المعتمد — واجهة عربية RTL بثمانية أدوار،
يغطي دورة حياة الطلب كاملة: **سلة ← تعميد العمليات ← تعميد المشتريات ← تجهيز B2B ← توصيل ← استلام ← تذاكر نواقص ← إشعار دائن**، مع محفظة مالية لكل سجل تجاري، فوترة، وشبكة فرنشايز ثلاثية المستويات (مانح ← ممنوح سوبر بمنطقة امتياز ← ممنوحون تابعون)، ومواقع فروع إلزامية على الخريطة.

> **مستوى الدقة:** الألوان والخطوط والقياسات والنصوص والتدفقات منقولة حرفيًا من التصميم المعتمد (hifi).

## 🟢 النظام لايف

**الرابط:** https://b2b-platform-ten.vercel.app

الواجهة تعمل على Backend حقيقي (Vercel Serverless Functions + **Neon Postgres**):
جلسات محفوظة في القاعدة (تبقى بعد تحديث الصفحة)، وكل عملية أعمال تُنفذ وتُخزن على الخادم
وتنعكس فورًا لكل المستخدمين.

### معمارية الـ Backend

```
api/
├── _lib/
│   ├── db.js        اتصال Neon + التسلسلات + الإشعارات
│   ├── http.js      جسم/رد JSON، كوكيز الجلسة، غلاف الأخطاء
│   ├── state.js     بناء لقطة الحالة الكاملة من القاعدة
│   └── logic.js     ⚙️ منطق الأعمال (تحقق صلاحيات + SQL) لكل أمر
├── auth.js          POST verify (جوال+OTP → جلسة) / role / logout · GET الجلسة
├── state.js         GET لقطة الحالة (تتطلب جلسة بدور)
├── command.js       POST { cmd, ...payload } → تنفيذ + لقطة محدّثة
└── admin/migrate.js ترحيل المخطط + التعبئة (محمي بترويسة x-migrate-key)
db/schema.sql        المخطط الكامل (15 جدولًا)
```

**نمط المزامنة:** الواجهة ترسل أمرًا (`orders.approve`، `tickets.resolve`…) عبر
`js/core/api.js`، والخادم يتحقق من دور الجلسة، ينفّذ داخل القاعدة، ويعيد
`{ msg, snapshot }` — اللقطة تُطبَّق على المخزن فيتحدث كل شيء. قائمة الأوامر كاملة في
`api/_lib/logic.js → COMMANDS`.

### تشغيل الترحيل (مرة واحدة أو لإعادة الضبط)

```bash
curl -X POST https://b2b-platform-ten.vercel.app/api/admin/migrate -H "x-migrate-key: <MIGRATE_KEY>" -d "{}"
```

`{"reset":1}` في الجسم يعيد بناء الجداول من الصفر. قيمة `MIGRATE_KEY` في
إعدادات المشروع على Vercel (Environment Variables).

### حدود النسخة الحالية (نقاط التوسعة)

- **OTP تجريبي** — أي 4 أرقام تُقبل؛ اربطوا مزود SMS في `api/auth.js`.
- محفظة العينة واحدة (سجل «مطاعم البلدة») — التعميم لكل سجل تجاري جاهز بنيويًا (`wallet.org_cr`).
- الحقول المركبة قليلة التغير (أصناف الطلب، فروع/فريق العميل) مخزنة JSONB — طبيعية للتقارير المعقدة لاحقًا.

## التشغيل

المشروع **بدون أي خطوة بناء (no build step)** — ملفات ثابتة تعمل على أي استضافة:

```bash
# أي سيرفر ملفات ثابت يكفي — مثلًا:
npx serve .
# أو
python -m http.server 8090
```

على ويندوز بدون Node/Python:

```bash
powershell -ExecutionPolicy Bypass -File dev/serve.ps1
```

ثم افتح `http://localhost:8090`.
(لا يعمل بفتح `index.html` مباشرة من القرص لأن ES Modules تتطلب سيرفر HTTP.)

**النشر:** ارفع المجلد كما هو على أي استضافة ثابتة (Nginx / S3 / Cloudflare Pages / Vercel static).

**الدخول التجريبي:** أي رقم جوال ← أي 4 أرقام OTP ← اختر أي حساب من الحسابات السبعة.

## المعمارية

- **بدون frameworks وبدون تبعيات** — JavaScript ES Modules قياسي. سهل الفهم، وسهل النقل لاحقًا إلى React/Next.js إذا رغبتم (البنية تحاكيها: state ← render ← actions).
- **حالة مركزية واحدة** في `core/store.js`. أي تعديل عبر `setState` يعيد رسم الواجهة كاملة (مع الحفاظ على تركيز حقول الإدخال — `core/dom.js`).
- **الأحداث مفوَّضة**: كل عنصر تفاعلي يحمل `data-action="اسم"` (+`data-arg`)، وكل حقل يحمل `data-input="حقل الحالة"`. السجل الكامل في `app.js`.
- **الأمان**: كل نص يدخله المستخدم يمر عبر `esc()` قبل الحقن في HTML.

### لإضافة صفحة جديدة
1. أضف تعريفها (عنوان + أيقونة) في `data/constants.js → PAGES` وأدرجها في `nav` الأدوار المعنية.
2. أنشئ `pages/my-page.js` بدالة `render(state) → html`.
3. اربطها في `app.js → PAGES_RENDER`.

### لربط Backend حقيقي
كل منطق الأعمال معزول في `actions.js` — استبدل التعديلات المحلية باستدعاءات API وأبقِ التواقيع.
الكيانات المطلوبة (مطابقة لبنية `seed.js`): `User, Org/Client, Product, Order, Ticket, Invoice, SavedList, ProductRequest, Franchisee, Notification`.

**متطلبات الخلفية الأساسية** (من وثيقة التصميم):
- RBAC يطابق مصفوفة الأدوار في `constants.js`.
- آلة حالات للطلب مع سجل تدقيق (من/متى لكل خطوة — تظهر في رحلة الطلب).
- محفظة كدفتر حركات ثابت (immutable ledger) يتبع السجل التجاري.
- أسباب الرفض/التعليق **إلزامية** وتصل نصًا لمقدّم الطلب.
- تذكرة نواقص ← إشعار دائن: `قيمة النقص × السعر × 1.15` تُقيَّد بالمحفظة وتنعكس بالفواتير.
- تفعيل الممنوحين حصريًا بيد B2B؛ رؤية العامل للأسعار سياسة منشأة (`POLICY.workerSeesPrices`).
- إيقاف تلقائي عند انتهاء السجل التجاري (وظيفة مجدولة).
- OTP حقيقي عبر مزود SMS (الحالي محاكاة).

## الأدوار الثمانية

| الدور | أبرز الصلاحيات |
|---|---|
| عامل المطعم | تصفح وطلب (الأسعار مخفية حسب السياسة)، تأكيد الاستلام والتبليغ عن النواقص |
| مدير العمليات | التعميد الأول (تعديل كميات / رفض بسبب)، إدارة العمال فقط |
| المالك / المشتريات | التعميد النهائي، المحفظة والفواتير، اقتراح منتجات، إدارة كاملة |
| مدير المالية | المحفظة والفواتير فقط |
| الممنوح بيسك (فرنشايز) | مثل المالك + قائمة أسعار المانح + محفظة مستقلة — يفتح فروعًا لمنشأته فقط |
| الممنوح سوبر (فرنشايز) | مثل البيسك + يمنح ممنوحين تابعين ضمن **منطقة امتيازه** ويتابع تحليلات شبكته |
| مانح الفرنشايز | تحليلات الشبكة كاملة، إنشاء ممنوحين (بيسك/سوبر بمنطقة)، متابعة الالتزام بالسداد |
| B2B سوبر أدمن | كل شيء: التجهيز، التذاكر، العملاء (إيقاف/تجميد)، الكتالوج، تعميد وتفعيل كل الممنوحين |

### واجهة الجوال (تصميم B2B App)
تحت عرض **820px** يُعرض تلقائيًا تطبيق الجوال المصمم (`js/mobile/`): شريط تبويبات سفلي مختلف
لكل دور، رئيسية مخصصة، شاشات push (تفاصيل الطلب، التعميد، الاستلام، الشحن، اللستات…)،
وBottom Sheets (السلة، الأسباب الإلزامية، الإشعارات…). **نفس الحالة والإجراءات** —
طبقة عرض بديلة فقط، فأي عملية على الجوال تنعكس فورًا لو فُتح نفس التطبيق على المكتب.

### مواقع الفروع (خرائط)
تحديد موقع الفرع على الخريطة **إلزامي** قبل إضافته (في إدارة فروعي وملف العميل لدى B2B).
النافذة `mapPick` تحاكي خرائط Google بدبوس وgeocoding تجريبي (`actions.js → mapDistrict/locFromPin`) —
عند الربط الحقيقي استبدلوها بـ Google Maps JS API مع الحفاظ على عقد `loc {x,y,addr,coords}`.
لكل فرع بطاقة بخريطة مصغرة ونافذة تفاصيل (طلباته، فريقه، إيقاف مؤقت/حذف).

## نظام التصميم

كل القيم في `css/tokens.css` — المرجع الملزم:
- **الألوان**: سماوي `#1BC4DB` (أساسي)، بنفسجي `#654E92`، والتدرج `#654E92 → #3C79F5 → #1BC4DB` للبطاقات المميزة.
- **الخطوط**: Almarai لكل العربي، **Quicksand لكل الأرقام والمعرفات** (`class="num"`).
- **الاتجاه RTL دائمًا**، العملة ر.س بأرقام إنجليزية وخانتين عشريتين، الضريبة 15% سطر مستقل.
- بطاقات بقطر 18px وحد `#E9E6F0` بلا ظل (الظل للنوافذ والدرج فقط).
